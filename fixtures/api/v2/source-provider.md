# Source provider component

`ResponsesSourcePlanner({ runtimeDir, apiKey, fetchImpl? }).generate(request, signal)` returns the shared strict `python_source` proposal. It never executes source or CAD. The operator must provision an existing private runtime directory, outside public assets, with trusted ownership. No SDK or dependencies are added.

The request contains `runId`, `requestId`, `attemptId`, `designId`, `inputRevisionId`, verified frozen `requirements`, `instruction`, nullable `acceptedSource: { revisionId, source, sha256 }`, and nullable `feedback: { attemptId, source, sourceSha256, checks, error }`. Source text remains literal data and is limited to 64 KiB of UTF-8. Instructions are limited to 2,000 characters, full canonical context to 256 KiB and canonical feedback to 128 KiB. Feedback uses shared check/error schemas, finite bounded JSON, unique registered checks, exact requirements and consistent candidate/geometry identities. Partial or empty checks can describe an interrupted attempt; they cannot establish acceptance.

Callers must bind the accepted source and input revision to actual store acceptance history, bind feedback source/checks/error to the actual previous attempt and CAD evidence, and mount the matching immutable STEP inputs. Hash consistency alone proves none of those facts. The fixed reference is `/input/reference.step`; `/input/baseline.step` exists only with an accepted baseline. The only generator output is `/out/candidate.step`. Independent execution, sealing, checking and explicit acceptance remain separate work.

Each attempt claims `runs/<runId>/attempts/<attemptId>/provider/` exclusively and syncs `dispatch.json` before dispatch. Every existing claim rejects reuse, including identical requests, concurrent calls, failed transport and crash recovery. A changed payload also rejects. Never remove a claim to retry a paid call. `receipt.json` is exclusively created with sanitized identity, fingerprint, proposal/source hashes, requested/reported model, actual response ID, token usage, HTTP/provider status and local completion status. Unknown metadata stays null. Source, response bodies, reasoning and credentials are not saved. Existing receipts are never overwritten, and no local receipt reads or cached proposals are used. Storage failure can leave a spent claim without a terminal receipt.

The next executor integration must enforce the full request budget of 180 seconds and at most three dispatch attempts, including provider calls and CAD stages, and supply its abort signal. This component performs one dispatch and has no internal retries or orchestration. Error retryability is false because an attempt identity cannot be reused.

The source-provider acceptance tests inject synthetic Responses output. Receipts label injected transport and do not establish live API, model generation, CAD or acceptance evidence.
